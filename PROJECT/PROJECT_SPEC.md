# PROJECT_SPEC

## 1. 프로젝트 개요

- **서비스명:**
- **한 줄 소개:** 소규모 매장에서 고객의 최근 구매, 방문 이력, 취향, 상담 내용과 다음 응대 메모를 한곳에 모아 직원이 몇 초 안에 고객 상황을 파악할 수 있게 해주는 고객관리 웹서비스.
- **해결하려는 문제:** 소규모 매장에서는 고객 정보가 엑셀, 메모장, 카톡 등에 흩어져 있어 직원이 고객을 응대할 때 필요한 정보를 빠르게 찾기 어렵다. 고객이 매장에 들어왔을 때 과거 구매 내역이나 마지막 방문 상황을 바로 확인하지 못하면 사장에게 다시 묻거나 여러 자료를 찾아야 하며, 이 과정에서 응대가 늦어지고 직원마다 고객을 이해하는 정도가 달라지며 중요한 후속 응대 내용도 놓치기 쉽다.
- **주요 사용자:**
    - **사장/관리자:** 고객 정보 전체를 관리하고 어떤 정보를 직원에게 공개할지 설정한다.
    - **직원:** 고객을 직접 응대하면서 고객 정보를 조회하고, 응대가 끝난 뒤 다음 직원이 참고할 메모를 작성한다.
    - 특정 업종에 한정하지 않고 단골 고객을 관리하는 여러 종류의 소규모 매장을 대상으로 한다.
- **핵심 가치:**
    - 이름과 전화번호로 고객을 빠르게 찾아 최근 상황을 몇 초 안에 파악한다.
    - 직원 간에 고객 정보를 공유해 이전 응대의 맥락을 이어간다.
    - 직원이 고객 정보를 확인하기 위해 사장에게 반복적으로 질문하는 상황을 줄인다.
    - 복잡한 입력 폼 대신 한 줄 메모로 응대 내용을 기록한다.
    - 한 줄 메모를 취향, 관심 상품, 다음 할 일로 정리해 다음 응대에 활용한다.
    - 고객 정보별로 직원 공개 여부를 구분할 수 있다.
    - 핵심 사용 경험은 **“고객이 들어오면 검색하고, 5초 안에 파악하고, 응대가 끝나면 한 줄만 남긴다.”**이다.

## 2. 서비스 사용 시나리오

### 2.1 사용자가 서비스를 사용하는 상황

가장 중요한 사용 순간은 고객이 매장에 들어왔을 때이다.

1. 직원이 고객의 **이름 + 전화번호**로 고객을 검색한다.
2. 검색 결과에서 고객을 선택한다.
3. 고객 상세 화면에서 다음 세 가지를 우선 확인한다.
    - 최근 구매
    - 마지막 방문일
    - 다음 응대 메모
4. 필요하면 취향, 관심 상품, 이전 구매 기록, 상담 기록을 추가로 확인한다.
5. 직원이 고객을 응대한다.
6. 응대가 끝난 뒤 한 줄 상담 메모를 입력한다.
7. 입력한 메모를 취향, 관심 상품, 다음 할 일 형태로 정리한 결과를 확인한다.
8. 필요한 경우 다음 응대 메모를 지정하고 공개 범위를 선택한다.
9. 저장 후, 다음 방문 때 다른 직원도 같은 고객 정보를 확인한다.

처음 방문한 고객의 경우:

1. 고객 검색 홈에서 신규 고객 등록을 선택한다.
2. 이름, 전화번호, 기본 메모를 입력한다.
3. 저장 후 고객 상세 화면으로 이동한다.
4. 이후 기존 고객과 동일하게 고객 정보와 응대 기록을 확인하고 관리한다.

초기 버전의 주문 이력은 직접 입력하는 방식을 전제로 하며, 정적 웹 MVP에서는 개발용 Mock Data에 샘플 주문 이력을 직접 작성해 사용한다. 엑셀 업로드·연동은 이후 단계에서 검토한다.

### 2.2 사용 전과 사용 후의 변화

#### 사용 전

고객 방문

→ 직원이 고객을 정확히 기억하지 못함

→ 엑셀 검색

→ 메모장 확인

→ 카톡 검색

→ 그래도 모르겠으면 사장에게 질문

→ 고객 응대

→ 응대 내용이 다시 메모·카톡 등에 흩어짐

#### 사용 후

고객 방문

→ 이름 + 전화번호 검색

→ 최근 구매·마지막 방문일·다음 응대 메모 확인

→ 바로 고객 응대

→ 직원이 상담 내용을 한 줄 입력

→ 취향·관심 상품·다음 할 일 자동 정리

→ 다음 방문 때 다른 직원도 바로 확인

## 3. 핵심 기능

### 3.1 고객 검색

- **기능명:** 고객 검색 기능
- **사용자 행동:** 고객이 매장에 왔을 때 해당 고객을 빠르게 찾고 싶다.
- **기능 설명:** 이름과 전화번호를 입력해 등록된 고객을 검색한다. 최초 MVP에서는 Mock Data를 대상으로 검색한다. 검색 결과에서 고객을 선택하면 고객 상세 화면으로 이동한다.
- **필요한 이유:** 서비스의 시작점이다. 고객 정보를 찾는 시간이 길면 핵심 가치인 “5초 안에 파악”이 무너진다.

### 3.2 고객 신규 등록

- **기능명:** 고객 신규 등록 기능
- **사용자 행동:** 처음 방문한 고객도 등록하고 싶다.
- **기능 설명:** 이름, 전화번호, 기본 메모를 입력해 신규 고객을 등록한다. 최초 MVP에서는 데이터베이스를 연결하지 않으므로 화면 흐름과 임시 저장 동작만 구현한다.
- **필요한 이유:** 기존 고객만 관리할 수 있으면 실제 매장 운영에서 계속 사용하기 어렵기 때문에 최소한의 신규 등록 기능이 필요하다.

### 3.3 고객 핵심 요약

- **기능명:** 고객 핵심 요약 기능
- **사용자 행동:** 고객의 핵심 상황을 한눈에 보고 싶다.
- **기능 설명:** 고객 상세 화면 상단에 최근 구매, 마지막 방문일, 다음 응대 메모를 가장 먼저 표시한다.
- **필요한 이유:** 직원이 긴 기록을 읽지 않고도 고객의 현재 상황을 빠르게 파악하고 바로 응대할 수 있게 하기 위해 필요하다.

### 3.4 고객 이력 조회

- **기능명:** 고객 이력 조회 기능
- **사용자 행동:** 과거에 어떤 일이 있었는지 확인하고 싶다.
- **기능 설명:** 구매 기록과 상담 기록을 시간순으로 보여준다. 복잡한 분석이나 통계는 제공하지 않고 단순한 타임라인 형태로 표시한다.
- **필요한 이유:** 고객의 맥락을 이해하고 이전 응대를 이어가기 위해 필요하다.

### 3.5 한 줄 상담 메모 입력

- **기능명:** 한 줄 상담 메모 입력 기능
- **사용자 행동:** 응대가 끝난 뒤 내용을 빠르게 남기고 싶다.
- **기능 설명:** 고객 상세 화면에서 직원이 응대 내용을 자유로운 한 줄 또는 짧은 문장으로 입력할 수 있게 한다.
- **필요한 이유:** 입력 과정이 복잡하면 직원이 기록을 남기지 않게 된다. 최소한의 입력으로 고객 정보가 계속 쌓이게 하기 위해 필요하다.

### 3.6 AI 메모 자동 분류

- **기능명:** AI 메모 자동 분류 기능
- **사용자 행동:** 한 줄 메모를 다시 항목별로 정리하는 수고를 줄이고 싶다.
- **기능 설명:** 입력된 한 줄 메모를 다음 항목으로 정리해 보여준다.
    - 취향
    - 관심 상품
    - 다음 할 일
    
    최초 MVP에서는 별도의 외부 AI API를 추가하지 않는다. 대신 화면 흐름과 결과 확인을 구현할 수 있도록 Mock Data 또는 JavaScript 기반의 고정된 Mock 분류 결과를 사용한다. 사용자는 분류 결과를 직접 수정할 수 있다.
    
- **필요한 이유:** 직원이 기록만 하면 이후 확인하기 좋은 형태로 정리되는 경험이 서비스의 핵심 차별점이기 때문이다.

### 3.7 다음 응대 메모 지정

- **기능명:** 다음 응대 메모 지정 기능
- **사용자 행동:** 다음 직원에게 꼭 전달할 내용을 남기고 싶다.
- **기능 설명:** 메모 정리 확인 단계에서 다음 방문 시 우선 확인해야 할 내용을 다음 응대 메모로 지정한다. 지정된 내용은 고객 상세 화면의 핵심 요약 영역에 표시한다.
- **필요한 이유:** 다음 직원이 “다음에 무엇을 해야 하는지” 바로 확인할 수 있어야 이전 응대가 다음 응대로 이어질 수 있다.

### 3.8 공개/비공개 설정

- **기능명:** 간단한 공개/비공개 설정 기능
- **사용자 행동:** 사장만 봐야 하는 정보와 직원에게 보여줄 정보를 구분하고 싶다.
- **기능 설명:** 메모 정리 확인 화면에서 정보의 공개 범위를 다음 두 가지 중 하나로 선택한다.
    - 직원 공개
    - 관리자만
    
    최초 MVP에서는 실제 로그인이나 역할 기반 권한 제어를 구현하지 않으므로 선택 상태를 Mock Data 수준으로 표시하고 저장 흐름만 구현한다.
    
- **필요한 이유:** 모든 정보를 직원에게 보여주기 부담스러운 상황을 최소한의 방식으로 처리하기 위해 필요하다.

## 4. 화면 구성

### 4.1 고객 검색 홈

- **화면명:** 고객 검색 홈
- **권장 파일명:** `index.html`
- **화면 목적:** 고객이 방문했을 때 기존 고객을 빠르게 찾거나 신규 고객 등록을 시작하는 서비스의 시작 화면.
- **주요 구성 요소:**
    - 이름 검색창
    - 전화번호 검색창
    - 검색 결과 영역
    - 최근 조회 고객
    - 신규 고객 등록 버튼
- **사용자가 할 수 있는 행동:**
    - 이름 입력
    - 전화번호 입력
    - 고객 검색
    - 검색 결과 선택
    - 최근 조회 고객 선택
    - 신규 고객 등록 시작
- **다른 화면과의 이동 관계:**
    - 검색 결과 또는 최근 조회 고객 선택 → **고객 상세 화면**
    - 신규 고객 등록 버튼 → **신규 고객 등록 화면**

### 4.2 고객 상세 화면

- **화면명:** 고객 상세 화면
- **권장 파일명:** `detail.html`
- **화면 목적:** 고객을 5초 안에 파악하고 바로 응대할 수 있게 하는 핵심 화면.
- **주요 구성 요소:**
    - 고객 이름
    - 전화번호
    - 최근 구매
    - 마지막 방문일
    - 다음 응대 메모
    - 취향
    - 관심 상품
    - 구매·상담 타임라인
    - 한 줄 상담 메모 입력창
    - 메모 정리 확인 화면으로 이동하는 버튼
- **사용자가 할 수 있는 행동:**
    - 고객 핵심 정보 확인
    - 취향과 관심 상품 확인
    - 과거 구매 기록 확인
    - 상담 기록 확인
    - 한 줄 상담 메모 작성
    - 입력한 메모를 메모 정리 확인 단계로 전달
    - 고객 검색 홈으로 이동
- **다른 화면과의 이동 관계:**
    - 고객 검색 홈에서 고객 선택 → **고객 상세 화면**
    - 한 줄 메모 입력 후 확인 → **메모 정리 확인 화면**
    - 홈 또는 뒤로가기 → **고객 검색 홈**

### 4.3 신규 고객 등록 화면

- **화면명:** 신규 고객 등록 화면
- **권장 파일명:** `new-customer.html`
- **화면 목적:** 처음 방문한 고객의 최소 정보를 빠르게 등록하는 화면.
- **주요 구성 요소:**
    - 이름 입력창
    - 전화번호 입력창
    - 기본 메모 입력창
    - 저장 버튼
    - 취소 또는 뒤로가기 버튼
- **사용자가 할 수 있는 행동:**
    - 고객 이름 입력
    - 전화번호 입력
    - 기본 메모 입력
    - 고객 저장
    - 등록 취소
- **다른 화면과의 이동 관계:**
    - 고객 검색 홈의 신규 고객 등록 버튼 → **신규 고객 등록 화면**
    - 저장 완료 → **고객 상세 화면**
    - 취소 또는 뒤로가기 → **고객 검색 홈**

### 4.4 메모 정리 확인 화면

- **화면명:** 메모 정리 확인 화면
- **권장 파일명:** `memo-review.html`
- **화면 목적:** 직원이 쓴 한 줄 메모를 분류한 결과를 확인하고 수정한 뒤 저장하는 화면.
- **주요 구성 요소:**
    - 원문 메모
    - 취향 분류 결과
    - 관심 상품 분류 결과
    - 다음 할 일 분류 결과
    - 다음 응대 메모 지정 영역
    - 공개 범위 선택
        - 직원 공개
        - 관리자만
    - 수정 가능한 입력 영역
    - 저장 버튼
    - 취소 또는 뒤로가기 버튼
- **사용자가 할 수 있는 행동:**
    - 원문 메모 확인
    - 분류 결과 확인
    - 취향 수정
    - 관심 상품 수정
    - 다음 할 일 수정
    - 다음 응대 메모 지정
    - 공개 범위 선택
    - 저장
    - 저장 전 취소 또는 이전 화면으로 이동
- **다른 화면과의 이동 관계:**
    - 고객 상세 화면에서 한 줄 메모 입력 후 이동 → **메모 정리 확인 화면**
    - 저장 완료 → **고객 상세 화면**
    - 취소 또는 뒤로가기 → **고객 상세 화면**

## 6. 개발 제약사항

- 로그인 / 회원가입은 최초 버전에서 구현하지 않는다.
- 로그인 / 회원가입이 필요해지면 나중에 Supabase와 연계한다.
- 데이터베이스는 최초 버전에서 연결하지 않는다.
- 데이터베이스가 필요해지면 나중에 Supabase와 연계한다.
- 최초 구현에서는 필요한 고객 정보와 이력을 Mock Data로 구성한다.
- 기존 기획에 명시되지 않은 외부 API는 사용하지 않는다.
- AI 메모 자동 분류는 기존 핵심 기능이지만, 최초 정적 MVP에서는 외부 AI API를 연결하지 않고 Mock 동작으로 구현한다.
- 명세에 없는 기능을 임의로 추가하지 않는다.
- 기존 기능의 의미를 임의로 변경하지 않는다.
- 핵심 기능과 핵심 화면 구현을 우선한다.
- 엑셀 업로드 및 연동은 최초 MVP 범위에 포함하지 않는다.
- 복잡한 사용자별 권한 관리 기능은 최초 MVP 범위에 포함하지 않는다.
- 공개 범위는 **직원 공개 / 관리자만** 두 단계로 유지한다.
- 구매 기록과 상담 기록은 복잡한 분석 없이 시간순으로 보여준다.
- 비전공자가 바이브코딩으로 이해하고 수정할 수 있도록 코드 구조를 단순하게 유지한다.

## 7. 기술 스택 및 개발 규칙

### 7.1 기술 스택

- HTML
- CSS
- JavaScript

### 7.2 기본 개발 규칙

- React, Vue 등 프레임워크를 사용하지 않는다.
- npm, Vite 등 별도의 빌드 도구를 사용하지 않는다.
- 별도의 서버 없이 정적 웹사이트로 구현한다.
- 화면 정의서에 정의된 주요 화면은 각각 하나의 HTML 파일로 구성한다.
- 공통 스타일은 CSS 파일로 분리한다.
- 공통 동작은 JavaScript 파일로 분리한다.
- 파일명과 폴더명은 영문 소문자로 작성한다.
- 필요한 샘플 데이터는 Mock Data를 사용한다.
- 로그인, 회원가입, 데이터베이스 기능이 필요해지는 경우 Supabase로 연계한다.
- Supabase 연계 전 최초 구현에서는 해당 기능을 실제 연동하지 않고 정적 UI 또는 Mock 동작으로만 구현한다.
- 최종 결과물은 Vercel에서 바로 배포할 수 있는 정적 웹사이트 구조로 만든다.
